# Acceptance checklist

## Visual
- [ ] Dark theme matches graphite/amber tokens.
- [ ] Light theme remains available.
- [ ] One primary studio workspace; no competing full-page studio shells.
- [ ] Script editor is the dominant surface.
- [ ] Voice controls are contextual.
- [ ] Audio output and generate action are visually distinct.
- [ ] Icons are consistent and have accessible labels.

## Responsive
- [ ] 320 px width has no horizontal overflow.
- [ ] 360 px width has no horizontal overflow.
- [ ] 390 px width matches the supplied mobile artboard proportions.
- [ ] 430 px width uses available space without stretching controls awkwardly.
- [ ] 768 px tablet layout is usable.
- [ ] 1280 × 720 desktop remains productive.
- [ ] 1440 × 900 desktop matches the intended hierarchy.
- [ ] Android safe areas and keyboard are handled.

## Functional
- [ ] Monologue generation uses existing service path.
- [ ] Multi-speaker generation uses existing service path.
- [ ] Voice cloning workflow is retained.
- [ ] BGM and SFX workflows are retained.
- [ ] Playback and export work.
- [ ] Projects save and load.
- [ ] Entitlements and quotas remain server-authoritative.
- [ ] Account and billing routes continue working.
- [ ] Errors provide recovery actions and technical details.
- [ ] No placeholder/mock actions remain in production UI.

## Engineering
- [ ] TypeScript passes.
- [ ] Lint passes.
- [ ] Tests pass.
- [ ] Production build passes.
- [ ] Android build passes.
- [ ] Audio resources are cleaned up.
- [ ] Accessibility checks pass.
